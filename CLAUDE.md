## The game
A toy-brick town where you train a car's Power and smash tapes. Loop: drive (x1) or floor it on a treadmill (x1..x120, locked by rebirths) to gain Power -> drive through the north gate up the tape track -> each tape snaps if Power >= its strength (wins), else it stretches like a rubber band and slingshots the car back -> spend Wins on cars (power multiplier + top speed) or Rebirth (power resets, +50% power each). Level/XP adds +10% per level. Free Boost chest: a Bloxity-signed-in player opens it after an hour of play (counted by the server while connected with the tab visible, kept across sessions; config `PLAY_REWARD`): +Wins worth 30% of the next car (or rebirth) and x2 power for 15 min, then the hour starts again. Guests are told to sign in; while it is locked a rewarded ad gives x2 for 2 min. Free Car podium (where "next car" stood): a car two tiers above the best one owned (`CAR_GIFT.jump`), free after a server-counted stretch of play (30 min, +15 min per car already gifted, at most 2 h; config `CAR_GIFT`), signed-in only; the car is owned and equipped on the spot. Gifted cars are a Rocket Edition (`CAR_GIFT.rocket`, `game.carLook`): at least performance kit 2 even on a hatch, rocket-orange afterburners, and a rocket exhaust in car.js (fire trail + smoke + accent glitter with the throttle, pilot flicker parked, a ring + spark kick on a hard launch).

Plaza layout: north = gate to the track, boost chest, Free Car podium, REBIRTH / CARS stalls; east = treadmills; west = terraced showroom; south = leaderboards (local bots + you) and the locked World 2 portal.

Three.js (vanilla) + Vite + Rapier (`@dimforge/rapier3d-compat`, top-level await, `build.target: 'es2022'`). Everything is procedural (canvas textures, synthesised audio). Font: Fredoka.

- `npm run dev` / `npm run build`. Deploy: `.github/workflows/deploy.yml` uploads `dist/` to Bloxity Hosting.
- All tunables are in `src/config.js`: identity, `TOWN`, `SPAWN`, `PHYSICS`, look (`TIME_OF_DAY`, `GRAPHICS_PRESETS`, `BLOOM`, `NEON`), and the game: `CAR` (handling), `CAR_CAM`, `TRACK` (tapes: power/wins), `ECONOMY` (rates, level curve, rebirth cost, boost), `TREADMILLS`, `CARS`, `HOUSE_COLORS`.
- All Bloxity SDK calls go through `src/bloxity.js` and must never throw.

## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path, not just a key. Use Pointer Events (`pointerdown/move/up`, check `e.pointerType`), never mouse-only events. Layout (implemented in `src/touch.js`): left-thumb virtual joystick -> `inputState.move`, right-side drag -> `inputState.look`, on-screen buttons for jump/sprint/mode/etc., pinch -> `inputState.zoom`. Everything still feeds `inputState` in `src/input.js` so game code stays input-agnostic. Pointer lock does not exist on touch; never rely on it.
- **Detection**: decide touch UI with `matchMedia('(pointer: coarse)')` / `navigator.maxTouchPoints`, not the user agent. Show touch controls only on coarse pointers; a device can have both.
- **Layout/UI**: HUD and menus use relative units (`%`, `vw/vh`, `dvh`, `clamp()`) and flexbox/grid, no fixed pixel layouts. Tap targets >= 44px. Respect notches with `env(safe-area-inset-*)` (viewport already has `viewport-fit=cover`). Text readable at 360px width. No hover-only interactions. Add `touch-action: none` on the canvas and game controls so the browser does not scroll/zoom.
- **Resize/orientation**: anything sized to the screen (camera aspect, renderer, HUD) must react to `resize` (covers orientation changes). Use `visualViewport` where the on-screen keyboard or browser bars matter.
- **Performance**: mobile GPUs are weak. Respect the `graphics_quality` presets in `src/config.js` (cap DPR, shadow map size, draw distance); default to a lower preset on coarse-pointer devices. Avoid per-frame allocations; keep draw calls and texture sizes low.
- **Testing**: check every UI/input change at a phone viewport (e.g. 375x812 and landscape 812x375) with touch emulation, plus desktop, before calling it done.

## Boxity SDK integration (docs.bloxity.io/#html5)
All calls go through `src/bloxity.js` (never throw). Integrated: auth/guest, avatar, synced settings, loading lifecycle (`loadingStep/End`, `gameplayStart/End`), reserved-area HUD layout, matchmaker (`net.resolveEndpoint`, party play comes with it), `game.updateRoom` + `?roomId=` launch join (invites / Open Rooms, `net.js`), friend join toasts (`playerJoined/playerInRoom` from the roster), `leaderboard.define` (boards in `config.js` `BOARDS`; scores + profile stats are reported by the server, backend `src/bloxity.ts`), ads (`onBreakStart/End` pause the loop and mute, `declareScreens` + `screen('gameplay'|'panel')`, rewarded ad on the boost chest while it is locked: `REWARDED`, token verified by the server), sign-in gate on the Free Boost chest (the server only opens it for a non-guest id; inside Boxity the toolbar signs in, never `auth.showAuthPopup`), chat bubble over the car, Reset Character -> `goHome`, Escape -> `portal.showMenu`. Not integrated: Gems (by request), death screen (`canDie: false`), emotes (no character). See `BLOXITY_CODE_METADATA.md`.
